## Story
**As a** usuário do sistema,
**I want** fazer login com e-mail/senha seguido de verificação biométrica facial,
**so that** apenas eu, com meu rosto confirmado, possa acessar o sistema.

## Acceptance Criteria
1. `POST /api/auth/login` com credenciais válidas retorna `{ challengeToken }` (JWT 5min)
2. `POST /api/auth/login` com credenciais inválidas retorna 401
3. `POST /api/auth/biometric-verify` com faceImage + challengeToken válido retorna `{ accessToken, refreshToken }`
4. Login sem biometria (apenas login/senha) não concede acesso ao sistema
5. accessToken expira em 15 minutos; refreshToken expira em 7 dias
6. `POST /api/auth/refresh` renova accessToken com refreshToken válido
7. `POST /api/auth/logout` invalida refreshToken no banco
8. Cada tentativa biométrica (sucesso ou falha) registrada em `BiometricRecord`
9. IP do dispositivo registrado em cada registro biométrico e de sessão
10. Componente `<BiometricCapture>` abre webcam e captura frame ao clicar em "Verificar"

## Dev Notes
**Fluxo completo de auth (2 etapas):**
```
1. POST /api/auth/login → { challengeToken } (JWT 5min, assina com JWT_SECRET)
2. POST /api/auth/biometric-verify → multipart:
     - challengeToken: string
     - faceImage: Blob (frame da webcam)
     - documentImage?: Blob (RG/CNH — obrigatório no 1º acesso)
   → { accessToken, refreshToken, user }
```

**JWT_SECRET** deve estar em `.env.local` como `JWT_SECRET=<random-256-bit-hex>`.

**Para face-api.js (recomendado para PoC):**
- Usar modelos: `ssd_mobilenetv1` (detecção) + `face_recognition_net` (embedding)
- Modelos devem ser servidos de `public/models/`
- Comparação no servidor: calcular euclidean distance entre embeddings (< 0.6 = match)

**IP:** Extrair de `request.headers.get('x-forwarded-for')` ou `request.ip` no Next.js.

**⚠️ CRÍTICO:** Nenhuma rota protegida deve ser acessível sem JWT válido. O middleware (Story 1.2) valida o accessToken em cada request.
